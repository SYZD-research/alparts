# Failure-mode analysis

Last reviewed: 2026-08-30

| Component / failure | Detection | Impact and containment | Recovery | Preventive mitigation / residual risk |
| --- | --- | --- | --- | --- |
| Node process crash or fatal rejection | supervisor state, liveness loss, structured fatal log | in-flight connections fail; PostgreSQL transactions roll back; already committed writes remain | supervisor restarts; startup verifies DB/object store/audit; clients reconnect and deduplicate | bounded graceful fatal shutdown; `kill -9` cannot drain, so durable invariants never depend on cleanup |
| Host reboot/power loss | external probe/supervisor, boot journal | whole service unavailable; volatile presence/rooms lost | filesystem/fsck as appropriate, start dependencies then app, verify readiness/audit and run smoke test | WAL/fsync/durable disk/UPS/operator tests; a single host is still an SPOF |
| PostgreSQL unavailable | readiness 503, pool/error metrics/logs | all authoritative reads/writes unavailable; no fail-open auth | restore connectivity or fail over external DB, verify timeline/schema/audit before app readiness | TLS, pool/connect/statement limits; HA/PITR supplied and tested externally |
| PostgreSQL corruption or lost timeline | integrity errors, audit mismatch, DB checks, synthetic correctness | writes stop; possible durable data loss | isolate, preserve evidence, restore to new DB, verify audit/checkpoint and objects, then controlled cutover | checksums/backups/WAL/replica testing are operator responsibilities |
| Object store (S3) outage | readiness 503, storage timeout/error and gate metrics | attachment upload/download unavailable; text metadata may remain stored | restore endpoint or fail over consistent bucket, reconcile scoped uploads/orphans | finite deadlines/gates; external replication/versioning not included |
| Malicious/buggy object listing | list count/key/byte/deadline errors | one attachment cleanup/reconcile fails with 503; process memory bounded | quarantine endpoint, inspect exact prefix, repair storage, retry scoped cleanup | strict prefix grammar and finite materialization; availability still depends on storage integrity |
| Network partition/DNS failure | readiness, dependency error rate, external network probes | affected dependency unavailable; no split-brain app writes because one app process is supported | restore route/DNS; if changing endpoints, verify identity/TLS and data timeline | numeric/explicit endpoints may reduce DNS dependency; multi-writer partition handling does not exist |
| Audit checkpoint write failure | structured critical event, readiness 503, authoritative mutation 503 | triggering DB mutation and audit row may already be committed; later audited or guarded authoritative mutations are blocked until the missed checkpoint is written; advisory presence/activity is not a safety input | a transient I/O failure is retried (at most every 2 s, with the full chain checks) on the next mutation or readiness probe and admission resumes on success; if it persists, drain ingress, preserve DB/checkpoint, fix storage and verify the descendant chain; integrity failures stay latched; do not blindly provision | atomic file replace/fsync and shared serialized admission; crash gap and same-authority deletion remain residual |
| Authoritative audit-admission saturation | `alparts_audit_commit_work`, 503 and structured request log | excess audited/guarded mutations are shed; accepted work remains ordered and memory cannot grow without bound | reduce abusive/accidental load, inspect DB/checkpoint latency, allow the queue to drain | one active + 64 pending with 30-second deadline; advisory presence cannot consume the gate; local gate is not cluster-wide |
| Audit checkpoint missing/rollback/tail truncation | startup/readiness/chain verification | startup or writes fail closed | incident procedure with independently retained checkpoint/backup; never create a new baseline until reconciled | separate checkpoint authority; no external WORM/multi-process witness yet |
| Password CPU flood or malformed stored hash | password gate saturation/503, execution timeout, event-loop metrics | login/registration shed; one corrupt login fails; existing sessions/traffic retain event-loop capacity | rate-block abusive sources, inspect account spray or hash corruption, restore a valid credential through the approved recovery path | cheap invite preflight, stored bcrypt format/cost validation, 30s Worker watchdog, source/account limits, separate public/authenticated pools of two Worker threads; public 0 pending through audit completion, authenticated 16 pending; KDF is outside DB/audit/key locks; local limits do not aggregate across replicas |
| Request/body/socket flood | 413/429, request and socket metrics, event-loop delay | abusive requests rejected within bounds | upstream rate/WAF action, preserve evidence, restart only if process unhealthy | parser-before admission, 512 KiB JSON, socket/body budgets; upstream DDoS protection external |
| Tenant metadata exhaustion | quota errors, invariant 503, DB capacity | offending tenant cannot create more bounded resources; normal channel capacity protected from DMs | archive/revoke eligible invitations; product lifecycle/manual data repair under backup | transactional quotas/indexes; no DM archive or general retention workflow yet |
| DB pool saturation/deadlock | waiting connections, statement timeout, PostgreSQL logs | latency/5xx/readiness degradation; no unbounded wait | identify query/lock, cancel through DB admin runbook, reduce load, roll back bad release | bounded snapshot queries, lock scoping/order, 15-second statement timeout; load benchmark pending |
| Disk full (app/audit/DB/object/backup) | host alerts, write/checkpoint/backup failure, readiness | writes or backups stop; deleting audit/DB files could destroy evidence | stop admission, expand/replace storage, preserve logs/checkpoint, validate filesystem/data, restart | quotas/log rotation/capacity alerts external; backup target must be separate and monitored |
| Certificate expiry | external TLS probe/expiry alert | clients/dependencies cannot connect; no insecure fallback | renew and atomically deploy cert, reload proxy/dependency trust, validate full chain/time | alerts at 30/14/7 days, overlap old/new trust; certificate automation external |
| Credential compromise | anomaly/audit/secret scan/operator report | attacker scope follows credential privileges; session or backend compromise possible | revoke/rotate, terminate sessions, replace dependent configs, audit, restore trust | secret files, hashing, least privilege; historic tracked development password requires external rotation confirmation |
| Bad deployment | canary/smoke/readiness/error-rate change | outage or incompatible behavior | stop rollout, restore prior immutable image; restore data only if migration made rollback unsafe | pinned artifacts, preflight, additive migrations, backups; no built-in orchestrated canary |
| Failed/incompatible migration | migration exit/preflight exception, startup/readiness journal/catalog mismatch | app remains stopped or unready; transaction should roll back applicable DDL | inspect on disposable copy, correct forward migration or restore verified backup to new target; never bless drift by editing the expected digest alone | exact bundled journal/hash plus PostgreSQL 16 public-catalog check, final-image migration/start CI, legacy-quota preflight, backup/restore gate; large index creation may need approved concurrent expand phase |
| Persistent schema drift after migration | `DATABASE_SCHEMA_CATALOG_MISMATCH`, readiness 503 | covered public constraint/index/column/trigger/policy/type changes cannot silently serve traffic | stop writes, compare a verified clone/artifact, forward-repair or restore, then rerun full migration/integration gate | repeatable-read bounded catalog fingerprint; row data, grants/roles, physical durability and transient DBA changes require separate database controls |
| No usable group member left (every member device lost, revoked or offline for 72 hours) | `historyRecoveryRequired`, devices waiting to be added, user report | devices outside the group cannot read or write; old ciphertext stays unavailable to devices without its keys | log in, use the retained recovery code or an approved device to approve the replacement and restore uploaded keys; revoke lost devices; then start the conversation again without earlier messages (step-up) | fresh start allowed only under the documented conditions, audited, managers notified; user-code archives exist; no organization escrow/threshold recovery |
| A member device cannot process a group update (faulty or malicious commit or Welcome, lost local state) | audit `channel.mls.member_package` with `rejoin: true`, `mls_rejoin_requests` rows, user report of the plain "joining again" message | that device cannot read new messages until it is added again; other devices are unaffected | another online member adds it again automatically; after three requests in a day, or if nobody can add it, the device (after 30 minutes) or a manager (after 15 minutes) starts the conversation again; remove a member whose commits keep causing this | rejoin limited to three per device and channel a day; audit names the committer device of every version |
| Backup failure | timer/service state, missing artifact/off-host copy, logs | RPO increases; running service may have a backup outage | fix cause, rerun supervised quiesced backup, copy off-host, perform restore test | non-overlap, restart trap, encryption/checksums; automatic off-host copy/alert not included |
| Restore verification failure | verifier non-zero/mismatch | artifact is not approved for recovery/migration gate | preserve artifact/log, diagnose tool/version/data mismatch, select earlier backup | empty-target and full object/table checksum checks; full application/client decrypt still separate |
| Accidental deletion | audit event, synthetic checks, user report | scoped or broad loss depending authority | stop writes, preserve audit/checkpoint, restore to isolated target, compare and controlled merge/cutover | app lacks bulk delete-all API; destructive scripts use narrow targets/acks; DB operator remains powerful |
| Ransomware/host compromise | EDR/operator indicators, altered files/checkpoint, secret misuse | availability, served client, metadata and same-host backups untrusted | isolate host, revoke credentials, rebuild clean host from pinned source/image, restore independent backup/checkpoint | off-host immutable/versioned copies and separate keys required; not supplied by repo |
| Region/cloud outage | external regional probes | current single-region deployment unavailable | recover in pre-provisioned compatible environment from verified off-region assets | no automatic region failover, DNS automation, or consistency protocol; treat as manual DR |
| Clock jump/skew | NTP/host alert, token/cert anomalies | session expiry and timestamps may be early/late; elapsed timeouts mostly unaffected | correct clock safely, restart if needed, inspect affected sessions/audit | UTC everywhere and monotonic timers for durations; distributed lease assumptions are not implemented |
| Cleanup scheduler failure/overlap | structured cleanup logs/absence, expired-row/object growth | storage leaks; foreground correctness continues | run one scoped cleanup after dependency recovery, inspect cap errors | single-process overlap guard and bounded scan; no durable job queue/DLQ |
| Browser/origin compromise | CSP report/external integrity signal/user report | attacker can invoke client-held keys and read plaintext available to endpoint | remove malicious deployment, revoke sessions/devices, rotate channel epochs, notify users | CSP/no third-party runtime scripts; no signed client/update/key transparency protection |
| Browser offline/realtime queue, conflict, timeout, or history saturation | client capacity/conflict/window/60s API timeout error, degraded voice quality, reconnect/state reconciliation | newest noncritical reconciliation/signaling work may be coalesced; cancelled verification retains its bounded slot until unwind; conflicting signed variants are quarantined rather than last-write-wins; unloaded/evicted history is recovered from REST; revocation cleanup remains fail-closed | reconnect/reload to rebuild authorized state, investigate a sticky conflict, page only within the visible resident window, send or discard existing outbox, retry the user operation explicitly | process-local verification provenance; caller-abort propagation; 100 outbox/device; 64 authorization/voice operations; 16 attachment runtimes; message verifier 1+1 coalesced with 30s lifetime, crypto batches 64, resident 1,000/channel and 5,000/32 channels |
| STUN/TURN outage or abuse | call failures/TURN telemetry/cost alert | voice fails or leaks peer IP metadata as documented; text unaffected | disable compromised ICE config, rotate short-lived creds, restore service | `turns:` and short-lived least privilege recommended; ICE service is external |

For every event, preserve timestamps in UTC, affected tenant/resource IDs, release/image digest, configuration version, external checkpoint, backup artifact digests, and the exact outcome of recovery verification. Never copy credentials or plaintext into an incident ticket.
