# Androidクライアント

[English](ANDROID.md) | 日本語

Androidクライアントは、同梱のReactの画面、暗号処理、暗号化した下書きと送信待ちメッセージ、
履歴の表示処理、添付ファイルの形式を、デスクトップ・Webクライアントと共有しています。これは
開発版のクライアントであり、Phase 2のセキュリティ受け入れ基準を満たしたものではありません。
iOSは、このLinuxでの実装の対象外です。

## ビルド

必要なもの: **javacを含む**JDK 21、Android SDKのプラットフォーム35、build-tools 35.0.0、
platform-tools、ルートのパッケージ定義で指定したNode/pnpm。`JAVA_HOME` と
`ANDROID_HOME` をそれぞれのインストール先に設定してから、次を実行します。

```sh
pnpm install --frozen-lockfile
pnpm android:build
```

APKは `packages/android/app/build/outputs/apk/debug/app-debug.apk` に出力されます。
このパスを指定して `adb install -r` でインストールします。デバッグ版のアプリケーションIDは
`app.alparts.android.debug` で、リリース版の `app.alparts.android` とは別です。
初回起動には、端末の画面ロックの設定と、HTTPSの接続先のオリジンが必要です。サーバーは
そのオリジンで `/api` と `/socket.io` を提供し、そのオリジンを `CORS_ORIGINS` に含めて
いる必要があります。暗号化されない通信や、証明書エラーを無視する手段は用意していません。

### Tailscale経由で開発用サーバーに接続する

PC上の開発用サーバーは暗号化されないHTTPで動くため、そのままではアプリから接続できません。
[Tailscale](https://tailscale.com/) を使うと、端末が信頼する証明書付きのHTTPSで、PCから
tailnet内に公開できます。

1. PCとAndroid端末の両方にTailscaleをインストールし、同じtailnetにログインします。
2. Tailscaleの管理画面のDNS設定で、MagicDNSとHTTPS Certificatesを有効にします。
3. `./dev.sh --tailscale` で開発用サーバーを起動します。`tailscale serve` で
   `http://127.0.0.1:5173` をtailnet内に公開し、その接続元をこの起動の間だけ許可し
   （`.env` は変更しません）、`https://your-pc.your-tailnet.ts.net` のようなアドレスを表示します。
4. アプリの接続画面に、そのアドレスを入力します。

このアドレスに接続できるのは、同じtailnet内の端末だけで、インターネットには公開されません。
`./dev.sh down` で公開を停止します。デバッグ版は信頼できる証明書のHTTPSサーバーであれば
接続でき、リリース版は証明書の固定設定に登録したホストだけに接続します。

接続画面とロック画面は、共通クライアントのダークカラーと既存のアルパカのロゴを使います。
フォームは表示領域が足りない場合にスクロールし、タブレットではカードの幅を一定に保ち、
システムバーとキーボードを避けて表示します。

同梱のログイン画面を開く前に、アプリはアカウントの認証情報を付けずに `/api/auth/me` を
確認します。期待する応答は、JSONのコンテンツタイプで、設定したオリジンと一致する
`Access-Control-Allow-Origin` を含む `401` です。これにより、`CORS_ORIGINS` に含まれて
いない接続先も検出します（そのままではログインのPOSTが拒否されます）。リダイレクトは
たどらず、確認に失敗した場合は新しいアドレスを保存しません。接続に失敗したときは再試行
するか、アドレスを修正できます。既存の鍵と下書きは、元の接続先に結び付いたまま残ります。

### ログインできない場合

HTMLはAPKに同梱しているため、以前のバージョンでは、接続先のバックエンドやフロントの
プロキシが停止して `502` を返していても、通常のログイン画面が表示されることがありました。
アカウントの認証情報を調べる前に、接続先の `/api/auth/me` の応答を確認し、停止している
サービスを再起動してください。認証前の `401` は想定どおりの応答です。新しくインストールした
直後に「ログイン状態が終了しました」という表示が出てはいけません。

HTTPSのオリジンは、WebViewと同じ方法で正規化するようになりました。`:443` は省略し、
スキームとホスト名の大文字・小文字は区別しません。以前は、既定のポートを明示して入力すると、
アプリ自身のリクエストやブリッジのメッセージを拒否してしまうことがありました。既定以外の
ポートは引き続き区別します。通信の失敗、サービスの停止、オリジンの拒否には、それぞれ別の
わかりやすいメッセージを表示します。認証情報はログに記録しません。

`packages/android/gradlew -p packages/android assembleRelease` で、署名なしのリリース用
APKをビルドできます。Androidのパッケージマネージャーは、更新のインストール時にAPKの署名を
検証し、同じ署名者であることを求めます。リリース用の署名の認証情報は、リリース担当者が
用意してください。デバッグ用の署名は、本番用の署名者ではありません。

Gradle wrapperのバージョンと配布物のチェックサムは固定しています。依存関係のチェックサムは
`gradle/verification-metadata.xml` にあります。依存関係を更新するときは、このファイルを
確認してください。`runtimeInventory` は、解決済みのAndroidの実行時コンポーネントを、
統合したSBOM用に出力します。

## ネイティブ側の境界

- HTML/JavaScriptを提供するのはAPKの資産だけです。APIの応答はデータとして扱い、画面遷移で
  権限を持つWebViewに外部の文書を読み込むことはできません。外部リンクはブラウザーで開きます。
- メッセージのブリッジは、オリジンの完全一致**とメインフレームであること**を確認します。
  制限のない `addJavascriptInterface` のブリッジはありません。フレーム、外部スクリプト、
  ワーカーは、ローカルの応答のCSPで禁止しています。
- AES-GCMによる鍵の保護には、取り出しできないAndroid Keystoreの鍵を使い、接続先の
  オリジンと値の名前を関連データとして認証します。Androidのバックアップと端末間の移行では、
  アプリのストレージを対象外にしています。端末の鍵は、試作段階のグループプロトコルの制限を
  引き続き受けます。これはMLSや鍵の透明性を実装するものではありません。
- WebViewを作成する前に、OSの認証情報の確認を求めます。バックグラウンドへの移動や無操作の
  時間切れでWebViewを破棄し、メモリー上の平文を消去します。システムのファイル選択画面は
  限定的な例外で、選択が終わるか無操作によるロックまで、非表示・一時停止の画面を残します。
- `FLAG_SECURE` により、スクリーンショットとタスク切り替え画面のプレビューを無効にして
  います。外部のカメラによる撮影や、侵害された端末からのデータの取り出しは防げません。
- 添付ファイルは、OSの文書選択画面を使い、サイズを制限した順次書き込みで保存します。
  キャンセルした場合、文書プロバイダーが許す範囲で書きかけの保存先を削除します。
- 音声の取得は、アプリのロックが解除されて前面にある間、設定した接続先からの音声に
  限ります。最初の要求でAndroidのマイクの権限を確認します。拒否した後も再試行でき、
  繰り返し拒否した場合はアプリの設定を案内します。OSからの結果は再開時まで保留し、
  キャンセル済みやロック中の要求に権限を与えることはありません。相手の通話音声は、
  メディア要素を別途タップしなくても再生できます。

## 表示言語

アプリは日本語と英語に対応しています。ネイティブの画面（接続、ロック解除、マイクやファイルの
ダイアログ）は端末の言語に合わせ、端末が日本語のときは日本語、それ以外では英語で表示します。
同梱の画面も同じ言語で始まり、サイドバーやログイン画面の🌐ボタンから切り替えられます。
選んだ言語はアプリ内に保存されます。

## タッチ操作

狭い画面では、会話を右にスワイプするとワークスペースとチャンネルの一覧が開きます。
テキストチャンネルを選ぶか、一覧を左にスワイプするか、会話の端をタップすると戻ります。
下部のナビゲーションバーは廃止しました。検索のすぐ左にある人のアイコンでメンバー一覧を
開閉でき、Escapeキーでも閉じられます。Alt+→とAlt+←で、チャンネル一覧とチャットを
キーボードで行き来できます。

メッセージを左にスワイプし、64 CSSピクセルを超えたところで離すと返信になります。自分の
メッセージでは、136ピクセルを超えて離すと編集になります。ドラッグ中は現在の操作を表示し、
しきい値より手前に戻すと取り消されます。縦方向の移動、複数の指での操作、キャンセルされた
ジェスチャー、操作できる要素の上では、操作は実行されません。返信と編集では入力欄に
フォーカスが移ります。下書きとスクロール位置は、チャンネル一覧を開いても保たれます。
非表示の会話では既読位置は進みません。

## 未完了の端末での確認と機能

配布の前に、実機で次を確認してください: Keystoreの無効化、再起動とロック、バックグラウンドで
の強制終了と送信待ちの復旧、Cookieの期限切れと失効、ファイルの選択と保存のキャンセル、
非常に大きな添付ファイル、悪意のあるオリジンやサブフレーム、アクセシビリティとフォントの
拡大。自動のJavaユニットテストでは、オリジンの検証と接続確認（サーバーの停止、オリジンの
拒否、リダイレクト、証明書エラーを含む）を確認しています。Android Lintとコンパイルは、
これらの実行時の確認の代わりにはなりません。

2026-09-05に、デバッグ版とリリース版のAPKのコンパイル、オリジンのユニットテスト、
Android Lintが成功しました。接続確認の回帰テストと、クライアントの認証・エラーのテストも
成功しました。デバッグ版APKのプラットフォーム署名は `apksigner verify` で確認しました。
ブリッジが5 MiBの添付チャンクを、サイズを制限したネイティブのメッセージへ欠損なく分割する
ことも確認しました。WebView 124を搭載したAndroid 15のエミュレーターで、端末の認証による
ロック解除、接続画面、通信できない状態からの回復、接続先のHTTPSエンドポイントを経由した
同梱のログイン画面への移動（`:443` を明示した入力を含む）を確認しました。これらの確認は、
実際のアカウントでのログインの成功や、上記の実機での受け入れ確認を完了したことを示すもの
ではありません。最終のAPKは、スマートフォン相当の1080 × 1920の表示領域でも確認し、ログインが
不要な「ログイン状態が終了しました」の表示なしに開くことを確認しました。無効なテスト用の
アカウントでは、稼働中のサーバーから想定どおりの認証エラーが返りました。エミュレーターは、
非公開の接続先へ到達するためにホストのCONNECTプロキシを使い、証明書の検証は有効のままでした。

2026-09-06に、Android 15のエミュレーターで、同梱のWebViewからマイクの権限の確認が表示される
ことを確認しました。拒否、再試行と説明、繰り返し拒否したときの設定の案内、有効な音声トラックの
取得の許可を、一時的な計測用ハーネスを使って確認しました。このハーネスは、WebViewの
デバッグを有効にしたり、アプリのセキュリティ設定を変更したりしていません。録音中にホームへ
移動すると、録音の操作が終わってWebViewが破棄され、戻ったときに端末の認証を求められました。
配布の前に、実機で、相手との双方向の音声、画面オフ時の動作、通話中のファイル選択を確認して
ください。

統合したデバッグ版のビルド、13件のAndroid JVMテスト、136件のクライアントテスト、Android
Lint、変更したクライアントのコンポーネントのlintが成功しました。Chromiumのタッチ入力の
確認では、返信と編集のしきい値、キャンセル、入れ子のナビゲーション、縦スクロール、下書きの
保持、非表示のチャットの既読位置、メンバー一覧の開閉、モーダルの背景を確認しました。
レイアウトは、320/390 CSSピクセルとデスクトップの幅で確認しました。一時的なテスト用データと
計測用の仕組みは、配布するアプリの外に置きました。

Push通知とバックグラウンド同期、OSの共有メニューからalpartsへの共有、アプリ内での接続先の
切り替えは実装していません。このアプリのインストールでは同じサーバーを使い続けてください。
アプリのデータを消去すると、端末内の鍵と未送信の下書きが失われます。消去する前に、別の端末
からアクセスを回復できるようにしてください。
