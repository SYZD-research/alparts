# デスクトップクライアント

[English](DESKTOP.md) | 日本語

最終確認日: 2026-09-04

`packages/desktop` のElectronクライアントは、Phase 1と同じクライアントをWindows・macOS・Linux向けにパッケージ化したものです。アプリの画面はインストーラーに同梱されています。利用者または運用者が選んだ接続先へ送るのは、APIとリアルタイム通信のリクエストだけです。接続先から配信されるJavaScriptを、権限を持つデスクトップのシェルに読み込むことはありません。

## 対応パッケージ

| プラットフォーム | アーキテクチャ | 出力 |
| --- | --- | --- |
| Windows | x64、ARM64 | 対話型のNSISインストーラー |
| macOS 13以降 | x64、ARM64 | DMGとZIP |
| Linux | x64、ARM64 | AppImageとDebianパッケージ |

ネイティブパッケージは、`.github/workflows/desktop.yml` によって、それぞれ対応するOS上でビルドします。展開済みのLinux x64パッケージは、ローカルでの動作確認にも使えます。

## 開発

まず通常の開発環境を起動します。別のターミナルで、同梱する画面をビルドしてElectronを開きます。

```bash
./dev.sh
pnpm dev:desktop
```

初回起動時は `http://localhost:5173` を入力します。開発用プロキシがAPIとリアルタイム通信をローカルのサーバーへ転送し、デスクトップアプリは同梱の画面を使い続けます。暗号化されないHTTPを使えるのは、ループバックアドレスでの開発時だけです。ループバック以外の接続先には必ずHTTPSを使ってください。管理された環境に配布する場合は、アプリを起動する前に接続先のオリジンを正確に設定します。

```bash
ALPARTS_SERVER_URL=https://chat.example.com pnpm dev:desktop
```

`ALPARTS_DESKTOP_DEV_URL` は、別に起動したViteの画面を使うための開発専用の設定で、ループバックアドレスだけを受け付けます。パッケージ化したビルドでは無視されます。

## ビルドとパッケージ化

```bash
pnpm desktop:pack
pnpm desktop:dist:windows
pnpm desktop:dist:macos
pnpm desktop:dist:linux
```

`desktop:pack` は、実行中のプラットフォーム向けに展開済みのパッケージを作成します。配布用の成果物は `packages/desktop/release` に出力されます。

このリポジトリからは、署名なしの開発用成果物を作成できます。一般向けのリリースは、管理されたネイティブのビルド環境で、組織のWindows AuthenticodeまたはApple Developer IDの認証情報を使ってビルドする必要があります。署名付きの更新配信、ダウングレードの防止、公証の方針、リリース用の鍵の管理は、Phase 2のリリース条件として残っています。署名のない開発用の成果物は、本番用のリリースではありません。

## セキュリティ境界

- レンダラープロセスでは、Chromiumのサンドボックスとコンテキスト分離が有効で、Node.js、シェル、webview、ファイルシステムへの直接のアクセスはできません。
- preloadが公開するのは、範囲を限定した設定、ロック、保護された秘密情報、ストリーム保存の操作と、表示言語の通知だけです。すべての呼び出しは、同梱した画面の最上位フレームからに限られます。
- 本番のページは、安全なCookieとSocket.IOのために設定済みの接続先のオリジンを保ちつつ、画面のルートに対する応答の本文は同梱のレンダラー資産から返します。
- APIとリアルタイム通信のルートはデータ専用です。スクリプト、スタイル、フレーム、最上位ページとして読み込むことはできず、リダイレクトでプロトコルの境界を回避することもできません。
- CSPにより、外部のスクリプト、フレーム、オブジェクト、ワーカー、別オリジンへのネットワークリクエストを遮断します。外部のWebリンクはOSが開きます。
- Electron fusesで、`ELECTRON_RUN_AS_NODE`、Nodeのオプション、CLIからの検査、fileプロトコルの特権、ASAR外のアプリケーションコードの読み込みを無効にしています。Cookieの暗号化は有効です。
- 接続先を変更すると、新しい接続先を読み込む前に、以前の接続先のCookieとストレージ、保護されたデスクトップ保管庫の名前空間を消去します。
- 端末の秘密鍵と端末内の状態を保護する鍵は、Electronの `safeStorage` で保護します。WindowsではDPAPI、macOSではキーチェーン、LinuxではSecret Serviceの実装を使います。Linuxで保護のない代替ストレージしか使えない場合、アプリは起動しません。
- OSのロック、スリープ、設定した時間の無操作、または「今すぐロック」で、復号済みのクライアントの状態を消去し、再び開くにはアカウントのパスワードが必要になります。ロック状態は、レンダラーを再読み込みしてもメインプロセスが保持します。
- 添付ファイルは5 MiBずつ復号し、内容を参照できない形のネイティブ保存ハンドルへ書き込みます。失敗やキャンセル時には、書きかけのファイルを削除します。保存したファイルには、種類にかかわらず、ブラウザーと同様にWindowsのゾーン情報またはmacOSの検疫情報を付けます。Linuxでは実行権限のないファイルとして保存します。危険な種類のファイルは、画面での確認も必要です。

デスクトップクライアントは、通常の画面のメッセージに診断用の詳細を表示しません。実装レベルの失敗の情報は、開発時のログとテストに置いています。

## 表示言語

アプリは日本語と英語に対応しています。起動時はOSの言語に合わせ（日本語以外の環境では英語）、接続先の設定画面やサイドバーの🌐ボタンから変更できます。アプリのメニューと、保存ダイアログなどのネイティブのダイアログも、アプリで選んだ言語に合わせて表示します。

## 検証

```bash
pnpm --filter @alparts/desktop typecheck
pnpm --filter @alparts/desktop test
pnpm --filter @alparts/client test
pnpm desktop:pack
packages/desktop/node_modules/.bin/electron-fuses read \
  --app packages/desktop/release/linux-unpacked/alparts
```

デスクトップのユニットテストでは、URLとオリジンの制限、同梱資産のパストラバーサル、保管庫の保存・鍵の更新・削除、設定の検証、添付ファイルのストリーム保存、サイズの上限、キャンセル時の後片付け、保存したすべてのファイルへの印付け、表示言語の切り替えを確認しています。ネイティブのインストーラーの実行、署名、OSの鍵保管の動作は、対象の各OSで別途確認する必要があります。
